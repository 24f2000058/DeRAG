# DECISIONS

## Milestone 0 — Project Scaffolding (2026-08-14)

- **Python dependency manager: `uv`.** Already installed on the dev
  machine; single `pyproject.toml` + `uv.lock`; `uv run` manages the venv
  without manual activation.
- **Python version: 3.11**, pinned via `.python-version`. Chosen over the
  system's 3.12 for broader wheel availability across
  sentence-transformers/torch/chromadb/langchain.
- **Hardhat language: TypeScript.** Config, deploy scripts, and contract
  tests are all `.ts`.
- **Node package location: nested inside `/contracts`** as its own
  self-contained npm package, isolating the Node toolchain from the
  Python side of the repo entirely.
- **Folder layout: flat Python package tree at repo root**
  (`pipeline/`, `retrieval/`, `blockchain/`, `storage/`, `generation/`,
  `scripts/`, `app/`) under one `pyproject.toml`, since a single Python
  process spans all of them at runtime. `/contracts` is the one exception,
  kept as an isolated npm package.
- **Test placement: single top-level `/tests/` directory**, files named
  `tests/test_<module>_<thing>.py`, no per-module `tests/` subfolders.
  Chosen to keep pytest discovery to one root and avoid re-deciding
  placement ad hoc in every later milestone.
- **Test frameworks:** `pytest` for Python, Hardhat's native Mocha/Chai
  (via `hardhat-toolbox`) for Solidity.
- **ChromaDB 1.x, not 0.5.x.** `pyproject.toml` pins `chromadb>=0.5` with no
  ceiling; `uv.lock` resolved it to `1.5.9`. This is intentional — the
  installed and target API is ChromaDB 1.x, not the 0.5.x line the floor
  might suggest. Recorded here so later milestones write retrieval code
  against the 1.x client API without needing to re-discover this.

## Deferred — Minor (from Milestone 0 final review, 2026-08-14)

Non-blocking findings from the final whole-branch review, parked rather
than fixed in Milestone 0. Pick up opportunistically or fold into whichever
later milestone next touches the relevant file.

- **`plans/.gitkeep` at repo root is dead weight.** Real planning docs live
  in `docs/superpowers/plans/` and `docs/superpowers/specs/`; nothing
  naturally lands in root `plans/`. Either drop the directory or document
  the split explicitly.
- **`app/` has no test contact.** `app/main.py` has no `__init__.py` and
  isn't in `tests/test_smoke.py`'s `MODULES` list — reasonable for a
  Streamlit script (importing it executes it), but it's the one Python
  directory with zero test coverage. Worth an explicit decision, not an
  omission.
- **`test_pytest_collects_and_runs` in `tests/test_smoke.py` is
  tautological** (`assert True`, can never fail). Harmless scaffolding
  tripwire, but it inflates the "N passed" count without adding coverage —
  `test_all_packages_importable` in the same file is the test doing real
  work.
- **README lacks a quickstart.** Compliant with the spec (quickstart is
  explicitly deferred to Milestone 10), but four lines now (`uv sync`,
  `uv run pytest`, `streamlit run app/main.py`, `cd contracts && npx
  hardhat test`) would make the repo self-explanatory sooner.
- **`contracts/tsconfig.json` carries inert template settings.**
  `outDir: "dist"` and `declaration: true` do nothing in a `ts-node`-driven
  Hardhat project that never runs `tsc` directly. Harmless.
- **`.gitignore`'s `.env` rule is exact-match only, not `.env*`.** Given
  the "keep `.env` discipline absolute" security stance, a real `.env.local`
  or `.env.development` generated by future tooling would slip through
  untracked. Zero cost today (nothing generates those files yet); worth
  broadening to `.env*` with `!.env.example` whenever `.gitignore` is next
  touched.
